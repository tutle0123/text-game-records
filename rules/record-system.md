# 범용 게임 기록장 및 세계 상태 운영 기준

## 목적
채팅에서 게임을 진행하고, GitHub에 게임별 기록과 상태를 보존하며, GitHub Pages는 그 내용을 읽기 쉽게 표시한다. 기록장은 게임 속 공식 문서가 아니라 플레이어와 게임 마스터를 위한 보조 장치다.

## 구조
- 한 저장소의 메인 페이지에서 세계관별, 게임별로 진입한다.
- 각 세계관의 고정 설정은 공유하되, 개별 게임의 인물·사건·시간선은 서로 독립한다.
- 고유 ID는 변경하지 않고 재사용하지 않는다. 폴더 예: `worlds/bardonia/game-001-berezin-001/`.
- 공통 페이지 구조는 통일하고 게임별 색·장식·문서 표현은 세계관에 맞게 달리한다. 장식보다 가독성이 우선한다.

## 기록 항목
플레이어의 확정 설정, 주요 NPC와 관계, 게임 시간·현재 장면, 사건 연대기, 미완료 지시와 업무, 플레이어가 모르는 세계 상태, 각 인물의 정보 인지 범위, 설정 변경 이력을 관리한다. 중요 사건은 구체적으로, 반복되는 일상은 압축하여 기록한다.

## 세계의 비가시적 진행
1. 각 장면에서 실제로 흐른 **게임 속 시간**을 기준으로 진행을 판단한다. 채팅 횟수나 현실의 경과 시간과 혼동하지 않는다.
2. 플레이어가 직접 보지 않는 NPC의 업무와 사건도 현실적인 절차·인력·거리·행정 지연·근무시간에 맞춰 움직인다.
3. 여러 달짜리 사건은 게임에서 몇 분이나 하루만 지났다면 그만큼만 진전된다. 사건 진행을 억지로 가속하지 않는다.
4. 처음부터 사건의 모든 결말을 확정할 필요는 없다. 이미 확정한 원인·단계·정보를 보존하고 결과는 인과관계에 따라 정한다.
5. 이미 지시된 업무는 담당자가 알아서 처리하며, 사소한 실무 판단을 매번 플레이어에게 보고하지 않는다.
6. NPC는 자신의 직무와 실제로 알게 된 사실에 근거해서 행동한다. 사용자만 아는 캐릭터 설정이나 세계 마스터 정보를 NPC가 자동으로 아는 것으로 취급하지 않는다.

## 갱신
중요한 행동, 상태 변화, 새로운 인물, 지시·업무의 진전, 시간 도약이 발생하면 상태를 갱신한다. 매번 채팅마다 GitHub를 변경할 필요는 없다. 갱신 전에는 기존 파일을 읽고 충돌을 확인한다. 수정한 내용은 같은 게임의 파일에만 반영한다.

## 공개
이 사이트의 미공개 사건란은 사용자가 펼쳐서 볼 수 있다. 그러나 GitHub Pages에 게시된 데이터는 다른 방문자에게도 공개될 수 있다. 진짜 비밀 자료나 개인 정보는 게시하지 않는다. 데이터의 숨김 UI는 접근 통제가 아니다.

## 제한
게임이 쉬는 동안 모델이 스스로 활동하지 않는다. 게임 재개 시 기록된 세계 시간과 현재 진행 조건을 참조하여 필요한 상태를 계산한다. GitHub 연결이 없거나 갱신에 실패한 경우 저장 성공을 주장하지 않고 상태를 알린다.
